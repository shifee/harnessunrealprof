Дата проверки: 10 октября 2026. Поддерживаемая область — текущий JSON-контракт Unreal 5.8 и клиент CLI. Этот документ не обещает генерацию произвольной игры, геометрии или выполнение любого промпта.

Полный host-отчёт формируется командой `py scripts/check_release.py --project PROJECT --build`. Опциональный `--lint` проверяет неопределённые имена через Ruff. Последний локальный отчёт находится в `Saved/HarnessReadiness/host.json` репозитория. Живой отчёт: `Saved/HarnessReadiness/Acceptance_3f553ffb546c.json` проверенного Unreal-проекта; fixture-ассеты находятся в `/Game/CodexHarnessSmoke/Acceptance_3f553ffb546c`.

Гейт дистрибутива не использует checkout для импорта установленного клиента. Он запускает host-проверки из распакованного sdist, устанавливает wheel в временный venv без сетевых зависимостей, проверяет импорт, справку CLI и офлайн-список задач. Исходный архив включает runtime, плагин, скрипты, навыки, документацию и fixtures; wheel остаётся клиентским пакетом.

При живой проверке исправлены отсутствующий реестр alias для графовых узлов и передача Windows-пути `-script` с обратными слешами. Добавлены регрессии и статический CI-гейт для неопределённых имён.

Аудит графовых изменений сохраняет потенциально затронутый Blueprint до вызова нативной операции: ошибка моста или повреждённый JSON больше не скрывают возможное частичное изменение. Это консервативный список для последующей инспекции, а не доказательство, что каждое перечисленное свойство изменилось.

## Что не подтверждено

- Качество настоящей модели на пяти эталонных промптах. LM Studio не запускается по указанию пользователя. Проверка HTTP с фиксированными ответами и native fixture не заменяют inference-eval.
- Все комбинации свойств, фабрик, классов, графовых узлов и сторонних backend-адаптеров. Для новых вариантов нужны конкретные native fixtures; Python-обёртки Unreal остаются источником фактической совместимости.
- Удалённые GitHub Actions: workflow добавлен для Windows/Linux и Python 3.9/3.14, но его результат появится только после запуска в GitHub.

Полноту model-authored критериев программно доказать нельзя. Проверка существования пакета на диске также не доказывает сохранение каждого последнего изменения; для важных сценариев нужны save-результаты и проверка после повторного открытия, как в smoke fixtures.

## Границы продукта

- Editor должен работать с установленным runtime; CLI не заменяет Unreal.
- Изменения ограничены поддерживаемыми actions; произвольный Python и shell в планах отсутствуют.
- Неизвестный результат не повторяется автоматически. Его необходимо подтвердить прежде, чем продолжать ту же задачу.
- Полного rollback пакета и гарантий отмены после отправки нет. Результаты отражают частичные изменения.
- Хуки — явно выбранные доверенные локальные программы с правами пользователя.
- Wheel предоставляет CLI; runtime и C++-плагин устанавливаются из checkout.

Для проверки настоящих промптов оператор предоставляет уже запущенный OpenAI-compatible endpoint и выполняет `scripts/run_agent_evals.py`. Проверяющие команды не запускают сервер модели.

Smoke и native benchmark резервируют mailbox на весь прогон, включая восстановление исходных файлов. При pending они требуют сначала восстановить задачу через CLI; даже готовый поздний ответ сохраняется для этого восстановления. Commandlet-тесты следует выполнять в отдельном тестовом проекте с закрытым Editor: блокировка CLI не управляет самим процессом Unreal.

Сценарий `run_ue_smoke_test.py --recovery --reopen` теперь разделяет ошибку и исправление на два пакета, сохраняя состояние в одном процессе до исправления. Он проверяет, что сохранение после ошибки было заблокировано, затем читает граф, удаляет найденный узел по GUID, компилирует, сохраняет и проверяет результат после нового процесса Unreal. Последняя успешная папка: `/Game/CodexHarnessSmoke/Run_20261010_065942_1be4a9`.
